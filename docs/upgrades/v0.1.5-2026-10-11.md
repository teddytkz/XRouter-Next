## Security / runtime hardening

### 1. Bounded request body (`src/sse/utils/boundedBody.js`)

`handleChat` dulu `await request.json()` — body besar di-parse penuh ke heap
dulu, baru dicek. Sekarang `readBoundedJson(request)`:
- Cek `Content-Length` lebih dulu → tolak **413** tanpa parse.
- Baca stream sambil hitung byte; lewat plafon → putus, buang chunk, **413**.
- Plafon default 8 MB, override via `NINEROUTER_MAX_BODY_BYTES`.
- **Fallback no-stream**: kalau `request.body` tak punya `getReader` (request
  sintetis di test/adapter), jatuh ke `request.json()`. Tanpa ini, test
  fake-request akan pecah.

Ditambah `PAYLOAD_TOO_LARGE: 413` ke `HTTP_STATUS` (`open-sse/config/runtimeConfig.js`).

### 2. `classify429` di `markAccountUnavailable` (`open-sse/utils/classify429.js`)

Sebelumnya 429 masuk ke `checkFallbackError` dengan backoff generik. Sekarang
cabang `status === 429` memakai `classify429` yang membedakan:
- `rate_limit` → cooldown 60s
- `quota_exhausted` (monthly/billing/credit) → ~1 jam
- `daily_quota` (reset tengah malam UTC) → lock sampai 00:00 UTC

Termasuk penanganan khusus Gemini ("Resource has been exhausted" = RPM limit,
bukan quota lock) dan Grok free-tier (`free-usage-exhausted` = daily).
Lock daily-quota yang sudah diset sebelumnya tidak lagi ditimpa backoff lebih
pendek.

### 3. Password strength policy (`src/lib/auth/password.js`)

Modul policy murni: `isStrongInitialPassword` (≥12 char & bukan placeholder),
`getInitialPassword(env)`, `isPlaceholderPassword`.

**Temuan review (Low, diperbaiki):** awalnya modul ini **dead code** — login
masih baca `process.env.INITIAL_PASSWORD || "123456"` verbatim. Konsekuensi
nyata: `INITIAL_PASSWORD=password` di produksi **diterima di login dan
mengeluarkan JWT penuh**, karena gate `mustChangePassword` hanya aktif kalau env
**tidak diset**. Diperbaiki dengan menyambungkan policy ke **dua** pembaca:

| File | Perubahan |
|---|---|
| `src/app/api/auth/login/route.js` | `getInitialPassword()`; nilai lemah → 503, bukan diterima. `mustChangePassword` pakai `isPlaceholderPassword(initialPassword)` (menangkap env yang diset ke default, bukan cuma env kosong). |
| `src/lib/auth/dashboardSession.js` | `verifyDashboardPassword` pakai `getInitialPassword()`; hapus `DEFAULT_PASSWORD` lokal. |
| `src/app/api/settings/route.js` | `PATCH` tolak `newPassword` lemah → 400. |

`reset-password` XR **tidak** disentuh: desainnya beda dari Vans (reset-ke-default
lokal, tanpa body, dijaga `dashboardGuard`). Menyalin versi Vans (set password
baru via body) akan mengubah perilaku, bukan memperbaiki.

### 4. Cooldown-aware retry (`open-sse/utils/cooldownRetry.js`)

**Temuan review:** util ini ter-port beserta test-nya, tapi **tak ada pemanggil**
— di Vans ia terpasang di loop account-fallback `chat.js`. Tanpa wiring, ini
dead code. Disambungkan ke `src/sse/handlers/chat.js`: saat `allRateLimited`
dengan `retryAfter` dekat (≤30s), tunggu sebentar lalu **retry loop sekali**
(batas 1/request, abort saat client disconnect → 499). Sebelumnya langsung 503.

## Ops features

### Durable proxy-pool fitness (sebelumnya write-only)

`open-sse/services/proxyPoolFitness.js` ditulis ulang: SQLite sebagai source of
truth + Map read-through cache. Sebelumnya XR hanya punya jalur *write*
(penandaan unfit) tanpa penyimpanan persisten dan tanpa permukaan ops.

- Tabel `proxyPoolFitness` (`src/lib/db/schema.js`), PK `(poolId, scope)`, 3 index.
- Migrasi `002-add-proxy-pool-fitness.js` (terdaftar di `migrations/index.js`).
- Repo `src/lib/db/repos/proxyPoolFitnessRepo.js` — SQL terparameter (nol
  string-interpolation nilai).
- Ekspor ditambahkan ke **tiga** barrel (`src/lib/db/index.js`,
  `src/models/index.js`, `src/lib/localDb.js`) — lupa salah satu = runtime
  "is not a function".

**Temuan review (HIGH, diperbaiki):** fitur ini awalnya **sepenuhnya inert**.
Rantainya:

1. `chatCore.js` membangun `proxyOptions` **tanpa field `proxyPoolId`** — padahal
   `getProviderCredentials` sudah menyetel `connectionProxyPoolId` di
   `credentials.providerSpecificData`. Akibatnya `freebuff.execute()` membaca
   `proxyOptions.proxyPoolId` = **selalu null**, sehingga `markPoolUnfit` **tak
   pernah menulis baris** — bahkan jalur *write* pun mati.
2. `isPoolUnfit`/`loadPoolFitness` nol pemanggil, dan `pickProxyPoolId`
   (`connectionProxy.js`) masih tanda-tangan lama tanpa strategi `smart`.

Jadi dashboard menampilkan "0 active blocks" selalu, teks "Smart rotation skips
pools marked unfit" bohong, dan tak ada pool yang benar-benar dilewati.

Akar lebih dalam: smart-routing Vans bersandar pada model **multi-pool per
koneksi** (`proxyPoolIds` + `proxyRotationStrategy` + `proxyPoolScope` di
`resolveConnectionProxyConfig`) yang **tidak ada sama sekali** di XR (grep: nol
kemunculan). Menyalinnya = rewrite blast-radius besar (halaman edit provider,
`ConnectionRow`, route proxy-pools) yang sudah dinyatakan di luar scope.

Perbaikan yang diambil (menutup loop tanpa rewrite itu):
- `chatCore.js` kini meneruskan `proxyPoolId` ke `proxyOptions` (dari
  `providerSpecificData.proxyPoolId` atau `connectionProxyPoolId`) — memulihkan
  jalur *write* **dan** guard strict-proxy `proxyFetch.js` yang juga membacanya.
- `freebuff.execute()` (satu-satunya executor yang menghasilkan sinyal
  `limited_ip`) kini membaca store durable lewat `isPoolUnfit` + `loadPoolFitness`
  (fail-open). Pool yang ditandai unfit benar-benar dilewati; "Clear" di
  dashboard benar-benar membuka blokir.
- Copy halaman diperbaiki agar jujur.

Catatan: `proxyOptions.strictProxy` juga tak pernah diset di jalur chat XR
(guard "jangan keluar via IP langsung" dorman). Itu masalah pra-ada yang
terpisah, **tidak** disentuh di batch ini.

**Temuan review (LOW, diperbaiki):** `clearProxyPoolFitness` memakai `LIKE
'${provider}::%'`; SQLite menganggap `_` sebagai wildcard satu-karakter, jadi
`clearAllPoolUnfit("scribe_v1")` ikut menghapus scope `scribeXv1::*`. Diganti
match prefix eksak via `substr(scope, 1, ?) = ?`. Test regresi ditambahkan.

### Route baru (semua di bawah `dashboardGuard` deny-by-default `/api/*`)

| Route | Fungsi |
|---|---|
| `GET /api/proxy-pools/fitness` | snapshot baris fitness aktif |
| `POST /api/proxy-pools/fitness/clear-all` | clear semua / per-provider |
| `POST /api/proxy-pools/[id]/fitness/clear` | clear satu `(poolId, scope)` |
| `GET /api/providers/[id]/gcp-projects` | daftar project GCP (gemini-cli/antigravity) |
| `POST /api/providers/bulk` | buat/update ≤500 koneksi api-key dalam 1 transaksi |
| `GET /api/usage/request-details/[id]` | satu record detail request |
| `GET /api/ready` | readiness probe (DB `SELECT 1`), 503 bila DB mati |

`/api/ready` satu-satunya yang ditambahkan ke `PUBLIC_API_PATHS`
(`src/dashboardGuard.js`); sisanya jatuh ke auth. Response `ready` hanya
`{ok, database}`, error DB di-log server-side.

- **GCP-projects**: URL Google di-hardcode → tidak ada SSRF. `params.id` hanya
  memilih koneksi tersimpan; bearer token tak pernah di-echo ke client.
- **Bulk**: `apiKey`/`name` di-trim & di-whitelist; duplikat `provider:name` →
  409; cap 500 dicek dua kali (route + repo).
